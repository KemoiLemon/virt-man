# Virt-Man

Personal VM manager: Proxmox is too heavy, raw libvirt is too light. A Rust
**daemon** controls libvirt; a **web UI** (with user auth, RBAC, and a daemon
proxy) sits on top.

## Components

| Part | Path | What it is |
|---|---|---|
| daemon | `daemon/` | Rust + axum; token-authenticated HTTPS API over libvirt (domains, networks, storage pools, volumes, lifecycle, native VNC console + virt-viewer handoff for SPICE, host metrics) |
| web UI | `web/` | Vite + TS SPA, served by the Rust backend in `web/server/` (users, RBAC, API keys, daemon connections + TLS-pinned proxy, daemon dashboard) |

## Install the daemon

```bash
cd daemon
sudo ./install.sh
```

This builds the daemon, installs it to `/usr/local/bin`, creates
`/etc/virt-man/{token,daemon.toml,tls/}`, generates a self-signed TLS cert
(SANs: localhost + hostname + host IPs, as an end-entity leaf so clients can
pin it), and enables `virt-man-daemon.service`. The daemon listens on
**`[::]:8443`** (HTTPS, both IP families on one socket).

The token is at `/etc/virt-man/token`. When adding the daemon to the web UI,
paste that token and confirm the cert fingerprint.

## Install the web UI

```bash
cd web
sudo ./install.sh
```

Builds the SPA (`web/dist`) and the Rust backend (`virt-man-web`), installs
the binary to `/usr/local/bin` and the static assets to
`/usr/local/share/virt-man/dist`, creates `/var/lib/virt-man`, and enables
`virt-man-web.service`. The web UI serves **HTTPS on `[::]:8006`** with an
autogenerated cert. First visit opens the setup wizard (create the admin
user), then add a daemon under Datacenter — its Dashboard tab shows host
CPU, RAM, VMs, networking and storage pools.

## Development

```bash
# web UI
cd web && pnpm install && pnpm dev                # Vite dev (proxies /api)
VIRT_MAN_WEB_LOOPBACK_HTTP=1 VIRT_MAN_WEB_PORT=8787 \
  cargo run --manifest-path web/server/Cargo.toml  # backend, loopback HTTP
```

## Notes

- Daemon token: read from `/etc/virt-man/token` (mode 0600).
- Web UI binds `[::]:8006` (HTTPS) by default — dual-stack, so `localhost`
  works whether it resolves to `127.0.0.1` or `::1`. Override with
  `VIRT_MAN_WEB_BIND` / `VIRT_MAN_WEB_PORT`; an explicit address is used as
  given, so `127.0.0.1` stays IPv4 loopback-only.
- Plain HTTP on the HTTPS port answers with a 308 redirect to `https://`,
  so `http://host:8006` works instead of returning a TLS protocol error.
- Certificates are pinned per daemon (not a CA), so existing daemons can be
  adopted by pasting their token and confirming the fingerprint.
